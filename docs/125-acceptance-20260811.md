## 已解決的重播阻塞與勘誤

### 開場正式追跡

先前的逾時不是 `renderFrame` 或船資料缺陷。下層前往拉米亞途中出現正式隨機戰鬥時，
`boardPhoenix` 的 fixture 把 battle 保留的 movement cooldown 當成一般 cooldown，無限送出
空白 `InputState`。修正為偵測 active battle 並透過正式戰鬥選單結束後再移動；沒有注入
座標、事件或資源。其後 clean replay 在 63.92 秒通過至 `THE END`，並輸出 runtime PNG：
`/tmp/dq3-e3-the-end.png`（14,386 bytes，SHA-256
`250a981f8f56aa3130e83c99d1b330a7474a5432b132203e2056d23c804fbfc9`）。

### Kandar 塔正常路線

先前 fixture 在 CTY10 人為建立 Lv1 單人、只檢查盜賊鑰匙門與 section transition，卻把
塔區原始隨機遭遇也納入同一測試，因 monster 23 全滅。這不是怪物數值錯誤；完整 E3
主線已以正常四人隊通過該段。fixture 現保留正式門／transition input，並以正式道具面板
使用聖水管理遭遇，讓其只測量自身聲明的路由契約。

## 工具判定

舊版 `tools/game_tester.sh` 與產物副本 `work/dist/verify/game_tester.sh` 已於本輪移除；
它們原先依賴 `dq3_remake` C／SDL、`/build/dq3_remake`、`DQ3_DEBUG` 與 `DQ3_INPUT`，
不是現行 `dq3_remake_ebitan/` 的驗收入口。本輪改用現行 Go `game` 測試二進位、
Docker＋Xvfb、正式輸入追跡與 `internal` 契約測試，避免把舊產品的綠燈誤當成現行
remake parity；根目錄 `tools/package.sh` 也已改為 fail closed 提示，避免誤啟動舊 C/SDL
打包流程。

## 收尾判定與下一個最小動作

最終判定：

1. 引擎／JSON pack／內部規則與 Android build pipeline 有可重現證據。
2. Android 只有 build-only；沒有 emulator／真機，因此不能宣稱 Android 動態驗收。
3. 完整 campaign E3 已通過；先前兩個 blocker 已依正式輸入路徑修正並回歸。
4. 原版比較仍只有可回查的 near-state 基準，尚未形成同輸入、同存檔、同 RNG 的
   像素／時序 V3 對拍。

下一個工作不再是重新證明 campaign，而是依獨立範圍補 V3 畫面／音效對拍與 Android
emulator／真機驗收。容器清理後不得留下專案相關執行中容器。
