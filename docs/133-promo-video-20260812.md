## 問題盤點

本輪把「沒有聲音」與「影片內容退步」分開檢查：

1. 6 月 28 日舊片的 MP4 其實含可解碼且非靜音的 32 kHz AAC 音軌，量測平均約
   `-19.6 dB`；因此無法只從位元流證明使用者端無聲的精確原因。新片改為相容性較高的
   48 kHz AAC，並提高到可驗收的整體響度。
2. `dist/dq3-promo-20260810.mp4` 完全沒有音訊串流；
   `dist/dq3-promo-20260811.mp4` 雖有 AAC 串流，整段卻是 `-91 dB` 的數位靜音。先前只檢查
   audio stream 存在，沒有解碼並量測聲音，是直接的驗收漏洞。
3. 8 月 11 日版本的 60 秒畫面大多反覆停在開場職業卡與同一城鎮對話；6 月 28 日版本至少
   有地表、日夜、戰鬥、解謎、建城、缺圖頭目與結局，敘事弧線反而較完整。
4. 舊 `tools/record_demo.sh` 仍錄製已停用的 C／SDL 產品，還要求主機執行 FFmpeg；它已改成
   失敗即關閉（fail-closed），不得再當成現行 remake 的推廣片入口。

## 新版安排

新版先用正式 v0.1.34 AppRun，在 Docker／Xvfb 內錄下 12 秒 Go／Ebitengine 動態開場：
`1989` 過場、職業巡禮與正式 Enter 輸入進選單。錄影以每秒抽格雜湊驗證至少三個不同畫格；
本輪實際得到五個，避免把靜態圖冒充動態錄影。

後段依玩家旅程排序現行 runtime 證據：母親送行、國王使命、四人地表 HUD、日夜、航海、
推石解謎、商人城、八頭大蛇兩種正確背景、巴拉摩斯、回補的 128／129 號怪物、不死鳥、
索瑪與 `THE END`。文字只作短標籤，不再用大量黑底卡片切斷節奏。

配樂使用本機、未加入 Git 的 MT-32 render，依序交叉淡化標題、地表、戰鬥、頭目與結局曲。
影片與配樂不因本地交付而改變原始素材的公開邊界。

## 可重現入口與 gate

- `dq3_remake_ebitan/Dockerfile.promo`：從既有 `dq3-ebitan-test:20260811` 增加鎖定發行版的
  FFmpeg／xdotool 工具鏈。
- `tools/capture_ebiten_promo_opening.sh`：只允許在 Docker 內啟動 AppRun、Xvfb、FFmpeg 與
  正式鍵盤輸入；有 trap 與外部硬逾時。
- `tools/build_ebiten_promo_video.sh`：只消費現行 Go／Ebitengine runtime 圖、動態片段與本機
  MT-32 render；缺任何輸入即停止。
- `tools/verify_promo_video.sh`：要求一條影像與一條音訊串流、1280×720、AAC 48 kHz 雙聲道、
  可聽音量、無長段數位靜音，最後完整解碼影音串流。

接觸表已逐段目視：開場是現行 AppRun 動態，不含舊 C／SDL 畫面；後段的 HUD、八頭大蛇
洞窟／沙漠背景、回補怪物與片尾均是現行證據圖。這是推廣片交付驗收，不把靜態 runtime 圖
擴張成全遊戲逐幀 V3 parity。
