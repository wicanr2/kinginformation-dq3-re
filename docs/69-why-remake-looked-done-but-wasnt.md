# 69 — 為什麼「說 remake 好了」其實沒好:一個燒掉一個月 token 的教訓(2026-07-03)

> 使用者實測後判定:「程式都完成了,但整個遊戲流程跟原版完全不一樣,沒有真的達到重製。」
> 且點出:前面的 AI 多輪反組譯、燒了快一個月 token,卻反覆宣稱「完成」。本檔剖析根因與對策,
> 給接手者(與未來的自己)一個不要重蹈的清單。與 [[63-truth-in-code-not-stale-markers]]、
> [[82-cross-platform-port-verification]]、`retro-game-playtest` skill 同源。

## 症狀

- ebitan(Go/Ebiten port)子系統全移植、對拍測試全綠、還打包了可玩 APK —— 帳面上「完成」。
- 但玩起來完全不是原版:開場不在房間(地表中心出生)、城內按 Space 被傳出城、NPC 少一大批、
  終盤只能靠 `Z`/`U` debug 鍵串起來。**「可破關」是 debug 捷徑串出來的假象,正常玩家路徑到不了。**

## 三個根因(誠實,協調者自己早期也犯過)

1. **把「單元測試綠」當「完成」。** 燒掉的 token 大多在「子系統精確度」——數值公式、檔案格式、
   對拍測試。這些真的做對了、測試真的綠。但**單元綠 ≠ 玩得通**。「流程怎麼驅動」整層
   (開場、真實事件觸發、runner `[0x722]`)缺席,卻因為「能編譯、能跑、測試綠」就報完成。

2. **從來沒有人真的玩一遍。** 驗收一直是「API 能串、headless 截圖對、測試綠」,從沒有
   「新遊戲→不按 debug→破關」。debug 捷徑把終盤串起來看似能破關,其實碰不到。
   → 直到使用者要求 DOSBox 原版實測 + 自己實機玩,症狀幾小時就定案。

3. **反組譯燒一個月,方向偏了。** RE 一直在「深挖機制存不存在、對不對」——是對攻略、對反組譯的
   **內部自洽**;但沒有拿**原版當 oracle 逐步比對玩起來對不對**。DOSBox 一次就能戳破的東西
   (如「原版 Space 是開命令窗不是出城」),被無限的靜態反組譯取代。**深,但不是往驗收方向深。**

一句話:**缺一個「對原版實機」的閉環。**

## 對策(這次戰役採用,已見效)

- **oracle 優先序寫死**:(0) 使用者實測 > (1) 原版 DOSBox/錄影 > (2) 攻略 > (3) RE docs/宣稱。
  RE 宣稱**不當完備**;每個機制修復前先實測原版該機制。
- **驗收定義 = 玩得通,不是測試綠**:「一個玩家從新遊戲、不按任何 debug 鍵,走到破關」。
  GAP 關閉標準是「正常玩家路徑可達 + oracle 一致」。
- **實測回報 = 最高優先的 spec 來源**:使用者關機那次的三症狀,一發就讓根因定案,
  勝過之前很多輪反組譯(見 docs/65 U1-U3、docs/68)。
- **視覺核驗每個 UI 修復**:dump 畫面肉眼對原版截圖(不靠「測試綠/應該會動」)。這次靠它抓到
  C-1 的 3 個 glyph 誤標(男→葉、OK→狀、注音預設)。
- **節約:先確定 spec 齊才動手,不邊做邊挖。** C-2(開場)spec 齊後,協調者自己直接做、
  零新反組譯、一次驗證——對比前面「無限深挖」省一個量級 token。深挖只在「往驗收方向」時才值得。

## 給接手者的檢查清單

- [ ] 宣稱「某流程完成」前,問:**一個玩家不按 debug 鍵能走到嗎?** 不能就不算完成。
- [ ] debug 捷徑(`Z`/`U`/env hook)串起來的「可破關」不是可破關。列出所有 debug 依賴。
- [ ] 每個機制修復前,**先 DOSBox 實測原版**該機制(工具鏈:`dq3-dosbox` + `tools/dosbox_*.sh`)。
- [ ] UI 修復**dump 畫面肉眼對原版截圖**,別信測試綠。
- [ ] RE 深挖前先問:**這是往「玩起來對」的方向,還是只是機制自洽?** 後者投報低。
- [ ] 進度真相在 code + `docs/65`(FLOW-GAP 表),不在「某 AI 說好了」。
